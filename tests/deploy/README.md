# 배포 도구 시험

배포 검증 도구가 **자기 목적을 실제로 지키는지** 확인한다.

```bash
tests/deploy/test_verify_package.sh     # [PASS] 실패 0 건 이어야 한다
```

## 왜 검증기에 시험이 필요한가

2026-09 작업에서 검증 도구가 자기 목적을 못 지킨 사례가 **세 번** 나왔다.

| 도구 | 결함 | 증상 |
|---|---|---|
| `verify_package.sh` | `echo \| grep -q` + `pipefail` 의 SIGPIPE | 정상 아카이브를 거짓 실패 |
| `verify_deploy.sh` | 대상 간 대조 누락 | 호스트 vs SIF 불일치를 놓침 |
| `verify_package.sh` | "없어야 할 것" 미검사 | 22GB 자기포함 아카이브를 통과 |

셋 다 **정상 케이스에서는 통과했다**. 그래서 시험은 "정상이 통과하는가" 가 아니라
**"막으려는 그 사건을 잡는가"** 로 짜야 한다.

## 무엇을 못 박았나 (9항목)

- 정상 아카이브 통과 — SIGPIPE 거짓 실패 회귀 방지
- `VERSION` 누락 검출 — v30~v32 에서 실제로 일어난 사건
- 지난 tar / SIF 를 삼킨 아카이브 검출 — 22GB 사건
- `bin/unified_analyzer` 누락 검출 — 목록 앞쪽 항목(SIGPIPE 결함이면 오작동하던 자리)
- `Version: unknown` 검출 — 추적 불가 빌드
- 최상위 디렉토리 2개, 손상 아카이브, 없는 파일
