## K-1 원인 (확정, 재현)

LS-PrePost 4.12 는 상태마다 메모리를 잡다가, 합이 `max_memory` 를 넘으면 그 뒤 상태에는 메모리를 주지 않는다
(`AllocStateMemory`, 0x9fa1d0). 그런 상태는 배치 영상에서 「min=0, max=0, at node# 0」 으로 그려진다.
`max_memory` 기본값은 `0.8 × wxGetFreeMemory()` 인데, 정적 링크된 wxWidgets 3.0 은 /proc/meminfo 의
MemFree 줄 다음을 「Buffers:」「Cached:」로 가정한다. 3.14 이후 커널은 그 자리가 MemAvailable 이라 두 값이
초기화되지 않은 스택 값이 된다 → 예산이 **시작 시점 MemFree(페이지 캐시에 따라 출렁) + 쓰레기값**.
그래서 비결정이고 MemFree ~1 GB 와 상관이 보였다.

- 재현: lsppconf `max_physical_memory = 20M` → 465 상태 덱의 마지막 프레임이 결함과 같은 모양(결정적).
- 처방: 작업자 HOME 의 `LSTC/LS-PrePost4.12/lsppconf` 에 `max_physical_memory = 1000G` → 정상.
  `LSPP_STATE_MEMORY=off` 는 처방이 아니다(작은 예산과 함께면 여전히 0).
- 예산을 없앤 뒤 실제 메모리가 모자라면 LS-PrePost 는 abort(rc 134)하고 mp4 는 moov 가 없다(1.6–1.8 GB 상한 시험).
  지금 실행 명령은 `wait $XVFB_PID` 의 종료 코드를 써서 이것도 성공으로 넘긴다 → 종료 코드 전달 + ffprobe 검사로 잡는다.
- 색 기반 0 프레임 검출은 넣지 않는다 — 0 프레임끼리도 모델 색이 다르고(순청색/연청색) 정상 전체 모델 프레임도
  98.6% 가 최저색이라 오탐·누락이 모두 난다.

## K-2 판정 규칙 (실덱으로 확인)

- 운영 덱(Test_005, 249 파일): 모든 가족 파일이 상태 뒤 EOF 표지(-999999)로 끝난다. 합 4,952.
- Test_Cum26x3: 중간 파일은 EOF 표지, 마지막 파일만 덜 써진 상태(1,136 워드 모자람)로 끝난다 — 정상 덱이다.
- 우리 D3plotWriter: 분할 때 EOF 표지 없이 상태 경계에서 끊는다(남는 워드 0).

→ 중간 가족 파일(1..N-2)이 EOF 표지가 아닌 「데이터 모자람」으로 끝났는데 남는 워드가 512 이상이면 **잘림 오류**.
  마지막 파일은 같은 경우 **경고**(앞 상태는 온전하다). 기본 파일(d3plot)은 상태 시작 위치 계산이 덱마다 달라
  오탐 위험이 있어 규칙에서 뺀다. 가족 번호에 구멍이 있는데 뒤 번호 파일이 있으면 오류.

## 성공 기준

1. 합성 덱 시험: 중간 파일 잘림·누락·열기 실패 → 예외, 마지막 파일 잘림 → 경고 후 앞 상태만, 병렬 = 순차. 수정 전 코드에서 FAIL.
2. unified_analyzer: 상태 읽기 실패 → rc 1 과 이유, 렌더 실패 → rc 3. 파이썬 rc 3 → 보고서 경고.
3. LS-PrePost 시험: 작업자 HOME 의 lsppconf 가 실행 뒤 `max_physical_memory = 1048576000K` 로 남는다(읽었다는 증거).
4. ctest·파이썬 시험 통과, SIF 안에서 실렌더 1회.
