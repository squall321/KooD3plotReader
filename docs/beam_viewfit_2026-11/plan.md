# 계획 — 빔 파트 응력 이력 · 카메라 타겟 맞춤 (2026-11-20)

## 왜

사용자 요청(11-20) 「카메라 타겟 맞추기와 빔도 마저 해줘」 — 리포트 그림 꾸러미 · 셸 이력 작업에서 미뤄 둔 두 항목.

- **빔** — `SinglePassAnalyzer` 의 파트별 이력은 솔리드 · 셸 · 두꺼운 셸만 돈다. 빔은 `BeamAnalyzer` 의 합력(축력 · 전단 · 모멘트)뿐이라
  deep 표에 「응력 이력 없음」으로 나온다. 덱이 적분점 응력을 기록했다면(`*DATABASE_EXTENT_BINARY` BEAMIP > 0) d3plot 에 값이 있다.
- **카메라** — LS-PrePost 개관 영상(타겟 강조)은 카메라를 보이는 모델 전체에 맞춘다. 타겟이 작으면 화면의 점이 된다. 단면 위치는 이미
  타겟 기준이고, 잘라내는 `_zoom.mp4` 는 단면 작업에서 꺼 두었다(v45). 타겟에 맞춘 개관이 없다.

## 무엇을

### 빔 파트 응력 이력
- d3plot 빔 블록(요소당 NV1D 워드) = 합력 6 + 적분점 5·BEAMIP(τ_rs · τ_tr · σ_축 · ε_p · ε_축) + 이력 변수 NEIPB·(3+BEAMIP),
  확장 제어 워드가 있으면 내부 에너지 워드 하나(BEMENG 위치). `ControlData` 에 NEIPB · BEMENG 을 읽어 넣는다.
- 배치는 스스로 검산한다 — BEAMIP 이 정수로 떨어지고 에너지 워드가 블록 경계에 있을 때만. 아니면 사유를 찍고 빔 이력을 만들지 않는다
  (셸 배치와 같은 규칙. 틀린 워드를 응력으로 읽지 않는다).
- 요소 값은 적분점 극값 — σ_vm = √(σ_a² + 3(τ_rs² + τ_tr²)) 최대, σ1 최대, σ3 최소, ε_p 최대. 삭제 요소 · 비유한 값은 뺀다.
- 적분점 값이 전 상태에서 0 인 파트(합력 빔 ELFORM 2 · 트러스 · 이산 빔)는 이력을 만들지 않고 사유를 찍는다. 0 을 「측정된 0」 으로 내지 않는다.
- 결과는 기존 `stress_history` · `max/min_principal_history` · `strain_history`(ε_p)에 `element_type: "beam"` 으로 붙는다.
  변형률 텐서 계열(축 변형률은 성분 하나)과 핫스팟 군집에는 넣지 않는다.
- 파이썬 — deep 표의 「빔 · 적분점 최대」 표식, 「응력 이력 없음」 문구, 그림 꾸러미(빔은 면이 없어 스냅샷 대상에서 빼고 사유).

### 카메라 타겟 맞춤 (`--view-fit target` · `--view-margin M`)
- LS-PrePost 개관 영상에서 타겟만 켠 채 카메라를 맞추고, 전체를 다시 켜서 찍는다. 잘라내기가 아니라 해상도가 그대로다.
- 렌더 작업 YAML 키 `view_fit: target` · `view_margin`(옛 분석기는 무시). 기본은 지금과 같다(모델 전체).
- deep CLI `--view-fit {model,target}` · `--view-margin`, 설정 파일 키. 효과 없는 조합(타겟 없음 · 소프트웨어 백엔드)은 `[설정]` 안내.
- cfile 순서(타겟만 표시 → 맞춤 → 여백 → 복원 → 다시 숨김)와 단면 뒤 `ac` 가 맞춤을 되돌리는지는 실제 LS-PrePost 로 재서 정한다.

## 검증
- 빔 — `ElasticBeam`(R13, BEAMIP 9, 탄성 · 음해법): `elout` 합력 → 보 이론 σ = N/A ± M·y/I 와 대조, lasso 적분점 배열과 대조.
  로컬 LS-DYNA R16 으로 작은 덱(적분 소성 빔 · 합력 빔 · 트러스, BEAMIP > 0)을 풀어 BEMENG 위치 · 비적분 빔의 워드 · ε_p 를 잰다.
  빔 적분점 없는 덱(`DynaAnalysis`, NV1D 6)은 사유 한 줄. 솔리드 · 셸 덱은 기존 출력과 같아야 한다(회귀).
- 카메라 — 실제 LS-PrePost 영상의 첫 프레임에서 타겟이 화면을 채우는지(맞춤 전 · 후 비교), 숨긴 파트가 다시 나오지 않는지,
  옵션 없이는 cfile 이 지금과 같은지.
- C++ 시험(tests/) · 파이썬 시험 전부.

## 위험
- 빔 이력은 분석 산출물을 바꾼다 — 빔 적분점을 기록한 덱에서 파트가 는다(순위 · 표 · 온톨로지 파트 수). 솔리드 · 셸 덱은 그대로여야 한다.
- R16 의 빔 배치(BEMENG · NEIPB)는 실제 데이터가 로컬 생성 덱 하나뿐이다 — 검산을 통과하지 못하면 만들지 않는 쪽으로 둔다.
- 카메라 맞춤은 cfile 을 바꾼다 — 옵션을 켰을 때만. 기본 경로의 cfile 은 한 글자도 달라지면 안 된다.
