# 핫스팟 군집 3D 인벨롭 — 전각도 리스크 맵 계획

작성 2026-09-13

## 1. 요지

지정한 **파트 하나**의 메쉬 위에 핫스팟 군집을 **3D 구 인벨롭**으로 얹고, **전각도
해석 결과를 한 화면에 모아** 각 군집이 어느 각도에서 나온 것인지 보이게 한다.
많이 겹칠 때는 점·반경을 모아 **컨투어(리스크 맵)** 로도 볼 수 있게 한다.

## 2. 지금 있는 것 / 없는 것

### 이미 있음 (deep report 핫스팟 탭, 런 1개 기준)
- 군집 **구 인벨롭** — `mesh3d`, 반경 = `radius_enclosing`
- 값에 따른 **색** — `stress_max` 컬러스케일
- **문자 라벨** — `#순위`
- **회전** — Plotly 직교 카메라
- 데이터: `center[3]`, `radius_enclosing`, `radius_rms`, `stress_max/mean`,
  `strain_max/mean`, `volume`, `element_count`, `peak_element_id`, `peak_time`

### 없음 (이번에 만들 것)
1. **실제 메쉬** — 지금은 파트 **경계상자 선**만. 삼각형 표면 없음
2. **전각도 집계** — 군집은 `koo_deep_report` 전용. sphere 리포트에 안 옴
3. **각도 라벨** — 문자가 `#순위` 뿐이라 어느 각도인지 모름
4. **컨투어(리스크 맵)** — 없음
5. **리스크 기준량 다양화** — 군집 criterion 이 응력 3종뿐
   (`VonMises`/`MaxPrincipal`/`MinPrincipal`). 변형률·에너지 기준 없음
6. **오프라인** — deep report 는 Plotly 를 CDN 에서 받는다

## 3. 렌더러 — 자체 캔버스 3D 기본 + Plotly 번들 옵션

| | 자체 캔버스 3D | Plotly 번들 |
|---|---|---|
| 의존성 | 0 | +3.60 MB |
| 오프라인 | 항상 | 항상 (번들 시) |
| 구현 | `drawDeviceMesh` 확장 + 회전 | 기존 코드 재사용 |
| 품질 | 기본 (음영·정렬) | 높음 (호버·범례·축) |

- **기본**: 자체 캔버스 3D. sphere 리포트의 오프라인 원칙(외부 스크립트 0)을 지킨다
- **옵션**: `--viewer plotly` 로 Plotly 를 **번들**(CDN 아님)
- **deep report 도 오프라인화** — 현재 `cdn.plot.ly` 참조를 번들로 교체.
  866KB → 약 4.5MB. 용량이 문제인 배포에는 `--viewer canvas` 를 기본으로 둘 수 있게 한다

## 4. 각도 선택

- **26방향 군** — F1~F6(면) · E01~E12(모서리) · **C1~C8(코너)**
  (사용자 표기 "V1~8" 은 이 저장소 규약상 C1~C8 을 가리키는 것으로 본다)
- **커스텀 각도 산포** — 각도 이름 목록 직접 지정
- **전체** — 캠페인의 모든 각도

## 5. 컨투어(리스크 맵)

버블이 많아 겹칠 때 개별 구 대신 **밀도/강도장**으로 본다.

- 각 군집을 `center` 중심, `radius_enclosing` 폭의 커널로 보고 합산
- 파트 표면(또는 파트 평면 투영) 격자에 누적 → 등고선/히트맵
- 가중치는 **리스크 값**(§6) — 개수만 세면 약한 군집이 많은 곳이 붉어진다

## 6. 리스크 기준량 — 응력 / 변형률 / 에너지

사용자 의도: *짧은 시간 응력이 튀는 것보다 에너지 차원이 더 효과적일 수 있다.*

### 6-1. 지금 데이터로 되는 것
군집이 가진 값은 **극값이 난 그 순간**의 것이다 (`stress_max`, 같은 시각의 `strain_*`).
전체 시간 적분값은 **없다**.

| 리스크 척도 | 식 | 데이터 | 성격 |
|---|---|---|---|
| 응력 | `stress_max` / `stress_mean` | 있음 | 현행 |
| 변형률 | `strain_max` / `strain_mean` | 있음 (`strain_available` 일 때) | 소성 누적 반영 |
| **에너지 근사** | `σ̄ · ε̄ · V` | 있음 | 피크 순간 변형에너지밀도 × 부피 |

**정직하게** — `σ̄·ε̄·V` 는 **참 파괴에너지가 아니다.** 시간 적분 `∫σ dε` 가 아니라
피크 순간값의 곱이다. 다만 응력만 보는 것보다는 낫다 — 응력이 잠깐 튀고 변형이 거의
없으면 작게, 실제로 항복해 변형이 쌓이면 크게 나온다. 그래서 **"에너지 근사(peak)"**
라고 이름 붙여 오해를 막는다.

### 6-2. 참 에너지를 쓰려면 (별건, 더 큰 작업)
`HotspotClusterAnalyzer` 는 요소별 **극값·그 시각·그 시점 변형률**만 받는다
(`elem_max`, `elem_max_time`, `elem_strain`). 시간 이력이 없다.
참 소산/파괴 에너지를 쓰려면 `SinglePassAnalyzer` 가 상태를 훑으면서
요소별 `∫σ dε` 를 누적하는 경로를 새로 만들어야 한다.
→ **이번 범위 밖으로 두고, 근사부터 넣은 뒤 별도로 제안한다.**

### 6-3. 군집 criterion 확장 (C++)
현재 `HotspotCriterion` 은 응력 3종뿐. 변형률 기준 군집을 쓰려면 열거형과
파서에 추가가 필요하다. **단, 색(리스크)만 바꾸는 것은 파이썬 쪽에서 가능** —
이미 `strain_*` 가 군집에 실려 있다. 그래서 단계를 나눈다.

- **1단계(이번)**: 군집은 기존 기준으로 잡되 **색칠 기준량**을 응력/변형률/에너지근사 중 선택
- **2단계(별건)**: 군집화 자체를 변형률·에너지로 하는 criterion 추가

## 7. 데이터 경로

전각도 캠페인에 아직 군집이 없다 (`Test_006`, `Test_001` 모두 `hotspot_clusters` 없음).
분석을 다시 돌려야 각도별 군집이 생긴다.

```
각 런 analysis_result.json (hotspot_clusters)
      ↓  koo_sphere_report/loader.py 가 수집 (신규)
지정 파트 + 각도 필터 + 리스크 척도
      ↓
payload: { mesh(make_stl 파트 추출), clusters[각도별], risk 척도 }
      ↓
3D 뷰어 (자체 캔버스 | Plotly 번들) + 컨투어 모드
```

## 8. 산출 형태

지정 파트 메쉬를 반투명으로 깔고 그 위에

- 군집 구 — 반경 `radius_enclosing`, 색 = 선택한 리스크 척도
- 문자 — `F1_Back #1` (각도명 + 순위)
- 각도 목록 체크박스로 켜고 끄기
- 모드 전환: **개별 버블** ↔ **컨투어(리스크 맵)**
- 마우스 드래그 회전 · 휠 줌

## 9. 범위 밖 (명시)

- 참 파괴에너지(`∫σ dε` 시간 적분) — §6-2, 별건 제안
- 변형률·에너지 기준 **군집화** — §6-3 2단계
- 전각도 캠페인 재해석 실행 — 사용자 판단 (라이선스·시간)
