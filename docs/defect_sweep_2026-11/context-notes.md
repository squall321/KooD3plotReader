### 1.2 결정 — 솔리드도 「층 있는 요소」 로 본다
- **요소 값 = 적분점 극값**(σ_vm 최대 · σ1 최대 · σ3 최소 · ε_p 최대, 변형률 e1 최대 · e3 최소 · e_vm 최대). 셸 · 두꺼운 셸 · 빔이 이미 이 규칙이다
  (`accumulateLayeredPartStats` 의 주석 「굽힘 최대는 표면 층이라 중립면만 보면 놓친다」). 그림 꾸러미(`figures/mesh.py` 의 `vm.max(axis=1)`)와도 같아진다.
- **버린 안 — 적분점 평균을 파트 최대로.** NINTSLD 1 과 같은 값이 되어 덱 설정에 무관해지는 장점이 있지만, 굽힘 최대를 절반으로 깎고(499.7 대 999.3)
  그림 꾸러미 · 셸 규칙과 어긋난다. 사용자가 일부러 여덟 자리를 기록했다면 그 값을 보려는 것이다.
- **버린 안 — 읽개(파서)에서 한 자리로 접어 넘기기.** `state.solid_data` 를 쓰는 곳이 전부 영향을 받고(내보내기 · 변환기 · C API),
  원시 값이 필요한 소비자가 값을 잃는다. 날것은 그대로 두고 소비자마다 명시적으로 고친다.
- **버린 안 — 겉면 쪽 적분점 넷만 골라 면 응력으로.** 요소 정식마다 적분점 순서를 알아야 하는데 재지 못했다.

### 1.3 배치 판정 — `include/kood3plot/data/SolidIpLayout.hpp`
- `per_ip = 6·IOSOL[0] + IOSOL[1] + NEIPH`. **`per_ip ≥ 7` 이고 `NV3D == 8·per_ip` 일 때만** 여덟 자리(stride = per_ip). 아니면 지금과 같은 읽기(자리 1, stride = NV3D).
  lasso 는 몫이 8 이상이면 여덟 자리로 보지만, 여기서는 정확히 맞을 때만 — 머리말이 확실히 말하지 않으면 동작을 바꾸지 않는다. 로컬 2,741개 덱은 전부 깨끗이 갈린다.
- 응력이 없는 덱(IOSOL[0] = 0)은 지금도 앞 6워드를 응력으로 읽는다 — 그런 덱은 로컬에 없고 이번 범위 밖이다(여덟 자리 판정에서도 빠진다).
- 변형률 — `ISTRN ≠ 0` 이고 `stride ≥ 13` 일 때 **적분점 블록마다** 뒤 6워드.
- 호출부는 요소 블록 전체(`base + NV3D ≤ solid_data.size()`)가 있는지 본다. NV3D 0(솔리드 워드 없는 덱)은 지금처럼 값 없이 지나간다.

### 1.4 쓰인 자리 · 같은 자리
- **안 쓰인 자리** — 자리의 앞 7워드(응력 6 · ε_p)가 전부 정확히 0 이면 뺀다. 사면체(뒤 네 자리 0) · 쐐기 같은 요소 때문이다.
  빼지 않으면 σ3 최소 · σ1 최대에 가짜 0 이 섞이고(전부 인장 · 전부 압축인 요소), 평균은 절반이 된다.
  요소 꼴 · 정식으로 자리 수를 정하지 않는 이유 — d3plot 에는 요소 정식이 없고, 값으로 가르면 정식을 몰라도 된다.
- 전부 0 이면(초기 상태) 첫 자리 하나를 쓴다 — 지금과 같은 0.
- **알려진 한계** — 일부만 하중을 받아 어떤 적분점이 정확히 0 인 육면체가 있다면 그 자리도 빠진다. 삼선형 요소는 절점 하나만 움직여도 여덟 적분점이
  모두 변형하므로 실제로는 초기 상태 말고 생기지 않는다.
- **같은 자리** — 쓰인 자리가 stride 전체에서 비트까지 같으면(memcmp) 한 자리로 읽는다. 1점 적분 요소를 여덟 번 적은 덱(배터리 · 테이프)이
  지금과 바이트까지 같고, 주응력 계산을 여덟 번 하지 않는다.
- **평균** — `p0 + Σ(v_k − p0)/n`. 값이 전부 같으면 반올림 없이 첫 값이 그대로 나온다.

**재현** — A1 을 넣는 순간 계약 §6 의 「정의는 리포트(정본)의 파트 최대와 같다」 가 깨진다. 같은 덱(ElasticBeam)에서 옛 추출기의 `/parts/vm_max_all`

- 그래서 자리 극값이 바깥 섬유의 해석해(1000)와 맞는다(999.30 · 1001.07, 빔 999.56) — 요소 중심이나 가우스 점이 아니라 겉면 절점의 값이기 때문이다.
  고치기 전의 「첫 자리」 는 **요소의 아무 모서리 하나의 응력** 이었다.
- 규칙은 어느 쪽이든 그대로 선다 — 자리 극값 = 그 요소가 적은 값 중 가장 큰 것, 자리 평균 = 요소 중심값(삼선형 · 선형 장에서 모서리 평균과 가우스 점 평균이 같다).

- 다른 덱(배터리 · 테이프)은 여덟 자리가 같은 값의 사본이라 이 구분이 드러나지 않는다.

**알릴 것** — kooremapper-4a(DynaForge)에 「여덟 자리 덱의 S1 요소 값 = 자리 최대, 계약 초안 5」 를 알린다(마감 때 — 답이 없다고 동의로 치지 않는다).

### 7.2 타깃 렌더의 자동 색 범위 → 타깃 파트 범위 — 「타깃 범위로 바꾼다」

**규칙**(`render::partFringeRanges`, 새 `TargetFringeRange.h/.cpp`) — 전 상태, 요소 값은 LS-PrePost 가 칠하는 「max IP. value」(4.5 실측):

- 파트별 단면 · 미끄럼 단면 — 파트마다 범위를 한 번에 내고(상태 훑기 한 번) 파트별 옵션 사본으로 건다(로그 `Part N fringe range: …`).
- 범위 줄의 숫자를 유효숫자 10자리로 — 스크립트 흐름의 고정 소수 6자리를 따르면 작은 변형률 범위(2.5e-06)가 0.000003 으로 뭉개진다. W 시험의 기대 문자열도 맞췄다.

**시험** — `tests/test_target_fringe_range.cpp`(새, 덱 없이) — 여덟 자리 육면체 · 사면체(0 자리) · 3층 셸 · 두꺼운 셸 · 빔만 있는 파트 · 상태 2 에서 지운 육면체(워드에 9e5),

첫 카드가 `         10.0000e+000.0000e+000.0000e+000.0000e+00      MECH         0` — LS-DYNA 고정폭 10칸인데 DA1..DA4 가 칸 사이 공백 없이 붙어 있다(LS-PrePost 가 쓰는 꼴).
`KeywordSetParser::tokenize` 는 쉼표 · 공백으로만 나눠(주석 「세트 카드의 필드는 공백을 품지 않으므로 안전하다」) `10.0000e+000.0000e+00…` 한 덩어리를 SID 로 읽다 실패했다.
같은 덱의 *SET_SEGMENT · *SET_PART 첫 카드는 `         1     0.000     0.000 …` 로 칸 사이에 공백이 있어 읽혔다. 사용자가 준 세트가 버려지는 결함(무시되는 입력).

**시험 먼저** — `test_keyword_set_parser` 에 고정폭 픽스처(붙은 첫 카드 NODE · PART · 제목 뒤 SEGMENT, 10자리 ID 두 칸이 붙은 줄, 칸에 맞지 않는 공백 구분 · 탭 구분).
고치기 전 5건 실패(붙은 꼴 넷 · SID 경고), 공백 · 탭 구분은 그때도 통과.

**바꾼 것** — `tokenize` 가 쉼표가 있으면 자유형(종전), 없으면 10칸씩 자른다(LS-DYNA 와 같은 규칙). 칸 안에 공백 · 탭이 든 줄(칸에 맞지 않게 나눈 옛 꼴)은 종전처럼 공백으로 나눈다.
부르는 곳은 앞 공백을 지운 줄 대신 원래 줄을 넘긴다(앞 공백을 지우면 칸이 어긋난다). 빈 칸은 종전처럼 뺀다.

**확인** — C++ 시험 렌더 켠 빌드 34 · 끈 빌드 9 통과(기존 픽스처 그대로). erode7 덱 세트: 절점 세트 다섯이 읽히고(SID 경고 0), 세그먼트 세트 CSV 는 그대로.

**덧 — 침식 덱의 떨어져 나간 절점** — 읽힌 절점 세트 1 · 3 · 4 의 피크 변위가 1.5e21 이다. lasso 로 따로 재도 절점 21314 의 상태 490 좌표가 ~1e21 이라 파일에 실린 값이다
(지운 요소에만 속해 떨어져 나간 절점이 발산). 파트 운동(`motion_analysis`)도 같은 덱에서 파트 21 최대 변위 1.529e21 · 파트 22 1.66e12 를 낸다 — 지표 정의(지운 요소에만 속한 절점을 뺄지)를 바꾸는 일이라 사용자에게 묻는다.

**deep contact_map 도 같은 꼴** — `core/contact_map.py` 의 `_int_fields` 가 공백으로만 나눠 세트 첫 카드가 붙은 덱에서 SID 를 잃고(그 접촉은 iface 로 강등),
접촉 카드 1 의 빈 칸(단일면 접촉의 MSID · MSTYP)에서는 뒤 필드가 당겨져 SSTYP 를 MSID 로 읽었다. 10칸 카드(세트 SID · 멤버 · 세그먼트 줄 · 접촉 카드 1)는
`_card_fields`(쉼표 없으면 10칸, 빈 칸은 None 으로 자리 유지, 칸 안에 공백이 든 줄은 종전대로)로, 요소 카드(8칸)는 종전 `_int_fields` 로 읽는다.
시험 먼저 — `test_contact_map.py` 에 붙은 세그먼트 · 파트 세트 첫 카드, 빈 칸 단일면 접촉. 고치기 전 2건 실패, 고친 뒤 통과(파이썬 여섯 패키지 전부 통과).
실덱 — erode7 · Test_006 DropSet.k · DynaAnalysis test.k 의 접촉 지도(26 · 27 · 2개)는 고치기 전과 같다(`.work/defect_sweep/setcard/cmp_cmap.py`) — 이 덱들은 LS-PrePost 가 칸을 다 채워 썼다.
