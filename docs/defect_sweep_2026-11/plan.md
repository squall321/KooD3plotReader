# 계획 — 묵은 결함 정리 (2026-11-21)

## 왜

v52 보고에 「요청받지 않아 손대지 않은 것이 둘 있습니다」 라고 적자 사용자가 답했다(11-21).

> 요청받지 않은것도 실제 고쳐야하는 부분이 있으면 고쳐.

그동안 작업하다 본 기존 결함을 「범위 밖 — 보고만」 으로 여러 판에 걸쳐 문서에 쌓아 왔다(`docs/beam_viewfit_2026-11/context-notes.md` 의
「고치지 않은 기존 동작」 목록 등). 이 작업은 그 목록을 다시 훑어 **실제로 고쳐야 하는 것** 을 가려 고친다.

가르는 기준은 하나다. 값이 틀린다 · 준 옵션을 말없이 무시한다 · 산출물이 깨진다 → 고친다. 기능이 더 있으면 좋겠다 · 취향 · 설계 선택 → 보고만 한다.
push · 배포는 이 요청의 승인 범위가 아니다(사용자 승인 뒤).

### A — 적분점 여덟 개 솔리드
- 머리말이 「요소당 워드 = 8 × (응력 6 + ε_p 1 + 이력 변수)」 라고 확실히 말할 때만 여덟 자리로 읽는다. 그 밖에는 지금과 같다.
- 솔리드도 셸 · 두꺼운 셸 · 빔과 같은 규칙으로 본다 — 요소 값은 **적분점 극값**(σ_vm · σ1 최대, σ3 최소, ε_p 최대, 변형률도 같은 식).
- 안 쓰인 자리(사면체의 뒤 네 자리 — 전부 0)는 뺀다. 여덟 자리가 같은 값이면(1점 적분 요소를 여덟 번 적은 덱) 지금과 바이트까지 같다.
- 핫스팟 · 군집 집계 · 피크 요소 텐서 이력은 셸 쪽 규칙을 그대로 따른다.
- 같은 배치를 읽는 제품 경로 — S1 추출기(적분점 최대 — 계약이 「리포트의 파트 최대와 같다」), 겉면 응력 · 변형률(쓰인 적분점 평균 텐서 =
  NINTSLD 1 이 적는 값), set 리포트의 segments 지표(적분점 극값), 소프트웨어 단면 렌더의 절점 평균(적분점 최대 — LS-PrePost 가
  기본으로 칠하는 「max IP. value」. 처음에는 평균 텐서로 고쳤다가 LS-PrePost 를 재 보고 바꿨다 — 결정 기록 4.5).
- 손대지 않는 것 — 원시 내보내기 계열. LS-PrePost 색 범위 계산(`computePartFringeRange`)은 LS-PrePost 가 칠하는 값을 잰 뒤(적분점 최대) 따로 가른다(표 W).

### Q — `parts:` 걸러내기
- `SinglePassAnalyzer` 가 `AnalysisConfig.part_ids` 를 읽는다 — 비었으면 전부(지금과 같다), 있으면 그 파트만.
- 빔 파트 · 핫스팟 군집도 같은 목록을 따른다. 모델에 없는 번호는 사유 한 줄.

### 단면 렌더에서 같이 찾은 것 (V · S · T · U · W · X)
- A2 의 넷째 줄(절점 평균)을 고치며 소프트웨어 단면 렌더 · LS-PrePost 렌더 경로를 읽다가 찾았다. 소프트웨어 단면 렌더는 제품(SIF)에서 켜져 있다.
- V — 셸 · 두꺼운 셸도 솔리드와 같은 규칙(저장된 층의 최대). 층 배치는 분석기 파트 이력(`layeredLayout`)과 같은 검사를 통과할 때만 믿고, 아니면 지금과 같다.
- S — 삭제 목록을 요소 순번(1부터)과 견준다. 다른 소비자(파트 이력 · 겉면 · S1 · 핫스팟)는 이미 그렇게 읽는다.
- T — `max_shear` = (σ1−σ3)/2. U — 요소 하나는 절점 하나에 한 번만 기여한다.
- W · X — LS-PrePost 를 실제로 돌려 재현한 뒤 고칠지 보고만 할지 정한다.

### 나머지
- B — 타겟 상자를 「모델에 있고 숨기지 않은 타겟」 으로만 만든다. 하나도 없으면 모델 상자.
- C — CLI 가 `--section-view` 를 주면 설정 파일의 「렌더 없음」 이 끄지 못한다. D — 도움말 문구.
- E — rc 3 메시지에 분석기의 `WARNING:` 사유 줄을 싣는다.
- L — `global_unmeasured` 표식을 파이썬이 읽어 최대를 「값 없음」 으로 둔다.
- R — `get_nv3d()` 가 머리말의 NV3D 를 돌려준다(이력 변수 있는 실덱으로 확인되면).
