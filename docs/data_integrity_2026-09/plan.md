## 왜 하는가

"특정 파트 ±Z 면 최대응력" 질문을 확인하다 **값이 조용히 틀리는** 결함이 줄줄이 나왔다.

1. **면 응력** — 내부 순번을 실제 요소 ID 로 찾아 0 또는 옆 요소 값, 셸 면 혼입, 퇴화 면 양방향 통과.
   → 36ea5db 로 수정(미배포).
2. **JSON 시계열 잘림** — `analysis_result.json` 의 이력 9종이 20점 초과 시 앞 10 + 뒤 10 + 문자열.
   deep report 이력 그래프·impact 시계열이 20점으로 그려진다. c6ef4ca 새 실행에서
   4952상태 → 20점, 남은 20점 안 최대 136 vs 실제 피크 472.
   원인은 "읽기 좋게" 라는 디버그 코드가 `pretty` 플래그에 묶여 저장 경로에 남은 것 (8f9ea8c).
3. **lsprepost libgtk** — SIF 안에 libgtk-3/gdk-3/atk/secret/notify 가 없다. 6/26 의 "번들에 있음" 판정은 호스트 ldd 착각.

원인 분석과 이력은 context-notes.md 에 있다.

## 목표 (검증 가능한 형태)

- JSON 이력·표면 시계열이 **전 상태**를 담는다 → 20점 초과 데이터로 실패하는 C++ 시험 + 실덱 새 실행에서 `len(data) == num_points`.
- 수치가 자릿수 때문에 뭉개지지 않는다 → 1e-9 스케일 값·1e-7 간격 시각이 JSON/CSV 왕복 후 구별된다.
- 보고서 차트 다운샘플이 **피크를 보존**한다 → 전체 시계열 최대값이 차트 데이터에 들어 있다.
- 옛 산출물(잘린 JSON)을 읽을 때 조용히 20점을 쓰지 않는다 → 같은 런의 CSV 로 복원하거나, 못 하면 사유를 남긴다.
- SIF 안에서 lsprepost 래퍼 환경 ldd not found 0개, 헤드리스 렌더 1회 성공.
- 호스트·SIF·node001 이 같은 커밋, 래퍼 env 없이 실행.

## 범위 결정 절차

1. 전수 조사 워크플로 — d3plot → unified_analyzer → JSON/CSV → Python 로더 → 보고서 경로에서
   잘림·피크 누락 다운샘플·정밀도 손실·조용한 0/자리표시 대체·인덱스 규약 불일치를 찾고 반박 검증.
2. 확정된 항목만 체크리스트에 올려 수정한다. 추측으로 고치지 않는다.
3. 수정 후 독립 검토 워크플로 + 실덱 새 실행으로 확인.
4. push → SIF 빌드(libgtk 포함) → deploy_from_sif → verify_deploy → node001 → 패키지.

## 설계 규칙 (이 작업에서 지킬 것)

- 예외를 던지지 않는다. 결측은 None + 사유. 데이터 없는 그림은 사유를 적는다.
- 실패를 0·자리표시 값으로 위장하지 않는다.
- 검증은 "값이 나온다" 가 아니라 독립 계산 대조. 옛 산출물은 증거로 쓰지 않는다.
- 의존성 검증은 SIF 안에서.
