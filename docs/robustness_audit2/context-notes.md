# 2차 강건성 수정 — 결정과 근거

## 2026-08-28 착수
사용자 지시: "다 수정해야겠지 문제있는것들은" — 확정 20건 전부 수정.

## 왜 mtime 단일 비교를 버리는가
7cd248d 는 `src.mtime > cache.mtime` 하나로 판정했다. 이 판정은 세 가지를 놓친다.
1. 생성은 `*INCLUDE` 를 깊이 8까지 따라가는데 판정은 마스터 덱 1개만 본다.
   실무 덱은 형상이 인클루드에 있어서 마스터는 잘 안 바뀐다 — 정면으로 어긋난다.
2. mtime 은 생성 **파라미터**(impactor part_id 등)를 담지 못한다.
3. 판정과 실행이 분리돼, 판정 후 실행 실패가 무음으로 남는다.
→ 소스 파일 집합 + 파라미터를 함께 담은 stamp 파일 비교로 바꾼다.

## 왜 선삭제를 금지하는가
1라운드 반증에서 "device_preview.json 은 파생 캐시라 재생성 가능하니 소실이 아니다"
라는 기각이 나왔다. 일리 있으나, make_stl 이 없는 환경에서는 재생성 자체가 불가능해
사용자는 그 세션에서 미리보기를 잃는다(impact 는 아무 안내도 없이). 파생물이라도
대체물 확보 전 파괴는 금물이라는 원칙을 택한다 — 임시 생성 후 원자 교체.

## TET10 판정 규칙
LS-DYNA `*ELEMENT_SOLID` 2줄형 카드2 는 절점을 최대 10개까지 담는다. 현재 파서는
앞 8개만 읽어 TET10(코너4+중간6)을 헥사로 오해한다(부피 8배 오차 실측).
규칙: 카드2 에서 유효 절점을 10개까지 읽고, 9·10번째가 유효하면 10절점 요소로 보고
**코너 4개만** 축퇴 헥사로 접는다. HEX20 은 별도 키워드(_H20)라 이 규칙과 충돌하지 않는다.
비표준 3카드 분할 배치는 대상 밖 — 대신 경고를 남긴다.

## 쓰기 검증을 '존재' 에서 '완결' 로
기존 검증은 ifstream 열림만 확인해서, ENOSPC 로 STL 이 절단되고 JSON 이 0바이트여도
"출력:" + exit 0 이었다(128KB tmpfs 실측). ofstream 을 명시적으로 flush·close 하고
스트림 상태와 기대 바이트 수를 대조한다.

## 2026-08-28 수정 후 적대적 재공격 — 내 수정이 들인 결함 15건
수정 20건을 4영역으로 재공격했다. 역전 45건 확인. 그러나 새 결함 후보 31건이
나왔고 상위 10건 검증에서 5건 확정 + 내가 독립 확인한 10건을 합쳐 15건을 고쳤다.

핵심 교훈 세 가지.
1. **'무음 금지' 는 payload 까지가 아니라 화면까지다.** note 를 만들어 넣고
   렌더하는 JS 를 안 붙였다. 커밋 메시지와 체크리스트는 '완료' 라고 적었는데
   사용자는 한 글자도 못 봤다. 검증 항목을 'HTML 에 사유 표기' 로 적어 놓고
   grep 으로만 확인한 것이 원인이다 — 브라우저로 봐야 했다.
2. **가드는 실전 경로에 붙여야 한다.** fixAng 를 Risk Ranking 의 소규모 경로에만
   붙였는데 이 프로젝트 기준 데이터가 1144각도라 실제로는 가상 스크롤 경로만 쓴다.
   즉 고쳤다고 한 그 결함이 실데이터에서는 그대로였다.
3. **강화가 검증 자체를 죽일 수 있다.** 미디어 검증 정규식을 '확장자 한정' 으로
   조인다는 것이 raw 문자열의 \' 때문에 문자 's' 를 제외해 16개를 0개로 만들었다.
   결측을 못 잡는 것보다 '전부 정상' 을 조용히 내보내는 쪽이 위험하다 —
   참조가 있는데 0개면 검증기 결함으로 판정하는 자기 점검을 넣었다.

그 밖에: 소스 미발견 시 멀쩡한 캐시를 버리던 회귀(구코드 대비), stamp 쓰기
실패 시 note 가 거짓말하던 문제, HEX20 을 TET10 으로 오판하던 회귀(1줄 예견으로
구분, 4요소 부피 이론값 대조), 빈 STL 을 성공으로 내보내던 문제, bool 각도값 통과,
사이드카 식별자가 없는 키를 읽던 문제.
