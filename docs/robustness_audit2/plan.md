## 설계 원칙 (이 저장소의 강건성 규율)
- 무음 실패 금지. 이상 상황은 경고나 비0 exit 로 드러낸다.
- 허구 값 금지. 측정 못 한 값을 지어내지 않는다.
- 파괴 전 대체물 확보. 사용자 산출물을 지우기 전에 새 것이 준비돼야 한다.
- 정직한 에러. 원인과 해법을 말하고 비0 exit.

## 그룹별 설계

### G1. 미리보기 캐시 무효화 재설계 (H1·H2·H3·M4·L6 = 5건)
mtime 단일 파일 비교를 **소스 서명(stamp)** 비교로 교체한다.
- 서명 = {소스 파일별 mtime·크기} + {생성 파라미터}. `.<name>.stamp.json` 에 보관.
- sphere 소스 = 시나리오 원본 .k + 그 .k 가 `*INCLUDE` 로 끌어오는 전 파일(깊이 8).
- impact 소스 = 생성에 쓰는 d3plot. 파라미터에 **part_id** 포함(M4).
- **선삭제 금지**. 임시 파일로 생성 성공 후 원자 교체. 실패하면 옛 캐시 유지 + 경고(H3·L6).
- unlink/권한 실패를 삼키지 않고 note 로 노출(H2).
- impact 에도 sphere 의 device_mesh_note 에 해당하는 안내를 신설.

### G2. make_stl 정확성·정직성 (H6·H7·L5·L7 = 4건)
- TET10: 2줄형 카드2 의 절점 필드를 10개까지 읽고, 9·10번이 유효하면 10절점 요소로
  판정해 **코너 4개만** 축퇴 헥사로 접는다 + 경고(H7).
- 쓰기 검증: 존재 확인이 아니라 flush/close 후 스트림 상태 + 기대 바이트 수 대조(H6).
- parts_csv 에 모델에 없는 PID 가 섞이면 경고(L5).
- 인자 파싱을 atoi → strtol(endptr·errno) 로 바꿔 오버플로·후행문자 거부(L7).

### G3. --from-json 입출력 계약 (H4·H5·M3·M5·L4 = 5건)
- impact 가드를 구조 검증으로 심화. faces 가 dict/list 가 아니거나 원소 형태가
  어긋나면 정직한 에러(H4).
- sphere from_json 에 동종 검증 신설. 결과 0건이면 성공으로 위장하지 않는다(H5).
- 사이드카 이름을 출력 HTML stem 기준으로 파생 + 덮어쓰기 경고(M3).
- 각도값 비수치(null/문자열)를 로드 시점에 거부(M5).
- --from-json 이 --format/--json 을 무시하면 경고하거나 실제로 처리(L4).

### G4. 지도 JS 방어 (M1 = 1건)
