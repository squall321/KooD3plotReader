# 시뮬레이션 결과를 AI 가 이해하게 — 개발 계획 (2026-11-27)

## 0. 목표

**「AI 가 이해한다」 의 뜻** — LLM · 에이전트가 결과 파일을 통째로 읽지 않고도
1. 정확한 수치와 그 **뜻 · 단위 · 믿을 수 있는 정도**를 알고,
2. 질문에 **근거(파일 · 필드)를 대며** 답하고, 없는 값은 「미계측(사유)」 이라 말하고,
3. 다음 행동(재해석 · 설계 변경 · 추가 후처리 · 다른 런과 비교)을 고를 수 있다.

**성공 기준**
- 골든 질문 세트에서 브리프만 준 LLM 의 정답률 ≥ 95%, 인용 수치는 원장과 일치(허용 오차 0 — 반올림 규칙 명시), 없는 값을 지어낸 답 0.
- 런 하나의 브리프 크기 ≤ 8 KB(마크다운) — 프롬프트에 그대로 넣을 수 있다.
- 브리프 · 온톨로지 · HTML 이 같은 수치 · 같은 품질 코드를 쓴다(셋이 다른 말을 하지 않는다).

## 1. 지금 있는 것 — 바탕

| 산출물 | 뜻 | AI 관점에서 빈 곳 |
|---|---|---|
| `analysis_result.json` · 파트별 CSV | 분석기 원장 — 정본 | 런당 수십~수백 MB. LLM 이 읽을 수 없다 |
| `result.json`(deep) | 파트 피크 · 한계 · 경고 요약 | 정의 · 시각 · 위치 · 품질 근거가 없다. 서술 없음 |
| `report.ontology.json` | DynaForge `cae_*` 어휘 객체(런 · 파트 · 파트 응답 · 접촉 · 핫스팟 · 하중 경로) | 지식 그래프 적재용. 서술 · 사건 · 품질 장부 없음 |
| `figures/manifest.json` | 그림 + 값 · 시각 · 카메라 · 캡션(기계 판독) | 브리프와 이어지지 않는다 |
| S1 (`s1.h5`) | DynaForge 뷰어용 촘촘한 배열 | 사람 · LLM 용이 아니다 |
| sphere · impact 소견(findings) | 규칙 기반 소견(심각도 · 파트) | deep 에는 없다. 도구마다 꼴이 다르다 |
| impact `solver_quality` | glstat 에너지 · 모래시계 게이트 → 신뢰 배지 | deep · sphere 에는 없다 |
| `campaign_metrics`(롱포맷 TSV) | 런 가로 묶기 | 서술 · 비교 요약 없음 |
| SmartTwinMCP(도구 48개) | 작업 제출 · 상태 · 후처리 실행 | **결과를 묻는 도구가 없다** |

**최근 결함 정리에서 본 것 — AI 가 그대로 믿으면 틀리는 값들**
- 침식 덱의 떨어져 나간 절점이 운동 지표를 차지(erode7 파트 21 최대 변위 1.529e21 — 파일 값) — 고치는 중.
- 없는 값을 0 으로 채우던 곳(deep 변형률 · 주응력, 세트 리포트 −1 · 0) — v55 에서 고침.
- 단위계 미검출(「덱 단위」), 첫 카드가 붙은 세트가 버려짐(실덱 절점 세트 840개) — 일부 고침.
→ 브리프에는 수치마다 **품질 표지**가 붙어야 한다. 품질 장부가 이 계획의 등뼈다.

## 2. 원칙

1. **원장이 정본** — 브리프는 파생물이고 원천 파일 · sha256 을 가리킨다. 브리프만 고쳐 값을 바꾸지 않는다.
2. **결정적 생성** — 브리프 · 서술은 규칙과 틀로 만든다. LLM 이 요약을 쓰지 않는다(환각 원천 차단). LLM 은 소비자다.
3. **없는 값은 없다고** — 0 · 추정으로 채우지 않고 사유 코드와 함께 비운다(이 저장소의 무결성 원칙 그대로).
4. **수치마다 단위 · 정의 · 출처 · 품질** — 「peak_strain = 유효 소성 변형률(적분점 최대, 셸은 층 최대)」 같은 정의를 값 옆에.
5. **층** — L0 한 줄 → L1 브리프(수 KB) → L2 질의(필요할 때만 원장 조각). 큰 것을 미리 다 주지 않는다.
6. **어휘는 DynaForge 정본(`cae_*`)과 같게** — 새 낱말을 만들지 않는다. 브리프 키 = 온톨로지 키.

## 3. 단계

### P1. AI 브리프 — 런 하나(deep)
`<줄기>.brief.json` + `<줄기>.brief.md`(report.html 곁, 온톨로지와 같은 짝짓기 규칙).
- **무엇** — 덱 · 시나리오 · 단위계(검출 근거 · 확신) · 상태 수 · 끝 시각 · 종료 상태 · 도구 판(VERSION).
- **핵심 결과** — 파트별 피크(값 · 단위 · 시각 · 요소 · 위치 · 정의), 판정(안전율 · 한계 출처 — 재료 카드 · 기본값), 최악 파트 순위.
- **사건 타임라인**(P3 와 이어짐) — 첫 접촉 · 피크 · 침식 시작 · 끝.
- **품질 장부**(P2) — 미계측 항목과 사유, 의심 값 표지, 해석 품질 배지.
- **그림 색인** — manifest 의 그림을 「무엇을 · 언제 · 어떤 값」 으로.
- **원천** — analysis_result.json · result.json · report.html 의 sha256, 온톨로지 꾸러미 키.
- `.md` 는 같은 내용을 결정적 틀로 쓴 글(한국어 기본, 키는 영어) — 프롬프트에 그대로 넣는 꼴.
- 완료 — Test_006 · ElasticBeam · DynaAnalysis · erode7 로 생성, 원장 대조 수치 일치 100%(시험), md ≤ 8 KB.

### P2. 데이터 품질 장부 — 브리프의 신뢰 근거
- 표준 품질 코드(예: `Q-UNMEASURED` 미계측 · `Q-ERODED` 침식 영향 · `Q-UNIT` 단위 미검출 · `Q-NAN` 비정상 값 · `Q-TRUNC` 잘린 시계열 · `Q-SOLVER` 해석 품질 경고)를
  분석기 · deep · sphere · impact 가 같은 이름으로 낸다. 지금 흩어진 사유 문자열(`peak_stress_reason` · `global_unmeasured` · `peak_disp_reason` …)을 코드 + 문장으로.
- impact `solver_quality`(glstat 에너지 비 · 모래시계 · 질량 증가)를 deep 에도 — 단일 런 신뢰 배지.
- 침식 통계(지운 요소 수 · 시작 시각 · 떨어진 절점 처리)를 품질 장부에.

### P3. 사건 타임라인 · 시계열 요약
- 첫 접촉(rcforc · S1), 파트별 피크 시각, 침식 시작 · 진행, 에너지 이상, 반발 — 사건 목록(시각 · 종류 · 파트 · 값).
- 피크를 지키는 솎기(이미 있는 `_extreme_indices`)로 시계열을 수십 점으로 — LLM 이 모양을 말할 수 있게.

### P4. 캠페인 브리프 — sphere · impact · federate
- 런 수십~수천을 한 장으로 — 최악 각도 · 위치, 분포(사분위), 이상치, 한계 넘는 런 수, 리비전 차이(federate).
- 런 브리프로 내려가는 키(case_key).

### P5. 결과 질의 창구 — MCP
- SIF 안 CLI `koo_brief`: `show <폴더>` · `parts` · `part <id>` · `series <part> <물리량> --points N` · `events` · `compare <A> <B>` · `worst --by <지표>`.
  응답은 작은 JSON + 출처(파일 · 필드 · sha256) + 품질 코드. 읽기 전용.
- SmartTwinMCP 도구 삼종(`script.sh` · `args.schema.json` · `meta.yaml`)으로 `result_brief` · `result_query` · `result_compare` 등록.
  작업 도구(`job_postprocess`)가 끝나면 브리프 경로를 돌려준다.

### P6. 평가 — AI 가 정말 이해하나
- 골든 질문 세트(런 · 캠페인당 20~30문항 — 피크 값 · 위치 · 시각 · 판정 · 결측 · 단위 · 비교 · 품질 경고).
  정답은 원장에서 기계로 뽑는다(사람 손 타지 않게).
- 브리프만 준 LLM · 질의 도구를 쓴 LLM 의 정답률 · 수치 정확도 · 지어낸 답 비율을 잰다. 판마다 회귀(판정 꾸러미처럼).

### P7. DynaForge · 포털 연동
- 브리프를 DynaForge 가 온톨로지 꾸러미와 함께 반입(계약 검토 요청), 포털 문서에 소비 규칙.

## 4. 순서 · 의존
P1(deep) → P2 → P3 → P4 → P5 → P7. P6 은 P1 부터 함께 자란다(브리프가 생기면 질문 세트도 생긴다).
진행 중인 결함 정리(침식 절점 · 고정폭 카드 · 원시 내보내기 선택지)가 P2 의 바탕이다 — 브리프가 틀린 값을 싣지 않게 먼저 끝낸다.

## 5. 정할 것
1. 브리프 언어 — 한국어 · 영어 · 둘 다(권장: 서술은 한국어, 키 · 코드는 영어).
2. 서술 생성 — 결정적 틀(권장) / LLM 생성 + 원장 대조 검증.
3. MCP 노출 — 읽기 전용 질의만(권장) / 재후처리 실행까지.
4. 평가에 쓸 LLM — 사내 모델 · Claude API(모델 · 비용).
5. 브리프를 DynaForge 계약에 넣을지(넣으면 계약 판 관리가 붙는다).

## 6. 위험
- 서술이 수치와 어긋남 → 결정적 틀 + 원장 대조 시험(P1 완료 조건).
- 브리프가 원장보다 늦게 바뀜(스키마 표류) → 브리프 판 번호, 시험이 원장 키를 직접 검사.
- 큰 덱 성능 → 브리프는 리포트가 이미 읽은 결과로 만든다(원장을 다시 읽지 않는다 — `ontology/deep.py` 와 같은 방식).
- 어휘 중복 · 엇갈림 → DynaForge 정본을 따르고, 새 개념은 정본에 먼저 올린다.
