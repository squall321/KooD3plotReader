# 핫스팟 군집 리포트 (Hotspot Cluster Report) — 계획

작성 2026-09-08 · 요청자 pyKooCAE(구조해석) 측 · 대상 KooD3plotReader

## 1. 배경과 문제

현재 파트별 결과에서 위치 정보는 **최대값이 난 요소 ID 하나**뿐이다
(`von_mises_max_element_id`, `max_principal_max_element_id` 등).

이것으로는 답할 수 없는 질문이 있다.

- 응력 집중이 **한 곳에 뭉쳐** 있는가, **여러 군데 흩어져** 있는가
- 각 집중부가 파트 안 **어디에**, **얼마나 큰 범위로** 존재하는가
- 그 범위 안의 **평균 수준**은 얼마인가 (최댓값 하나는 특이점일 수 있음)

설계 검토에서는 "최대 응력 450 MPa" 보다 "좌하단에 반경 1.2 mm 덩어리 하나,
평균 380 · 최대 450" 이 훨씬 실행 가능한 정보다.

## 2. 목표

파트별로 **상위 X% 요소를 공간 군집화해 덩어리 단위로 보고**한다.

덩어리마다 다음을 기록한다.

| 항목 | 내용 |
|---|---|
| 중심 좌표 | 응력 가중 평균 위치 (x, y, z) |
| 포함 반경 | 중심에서 가장 먼 구성 요소까지의 거리 |
| RMS 반경 | 중심 기준 제곱평균 거리 — 뭉침 정도 |
| 요소 수 | 덩어리를 이루는 요소 개수 |
| 응력 | 평균 · 최대 (von Mises) |
| 변형률 | 평균 · 최대 |
| 피크 정보 | 최대값 요소 ID와 그 시각 |

## 3. 결정된 설계 (사용자 확정 2026-09-08)

### 3.1 군집 기준 — 거리 임계값

요소 중심 간 거리가 임계값 이내면 같은 덩어리로 묶는다(단일 연결 군집화).

- 임계값 기본값은 **해당 파트 요소 대표 크기의 배수**로 준다 (기본 1.5배).
  절대 길이로 주면 메시 밀도가 다른 파트에서 의미가 달라진다.
- 요소 연결성(면 공유) 방식은 **채택하지 않는다.** 핫스팟은 얇은 틈이나
  분리된 메시를 건너 이어지는 경우가 있고, 연결성 방식은 이를 별개 덩어리로 쪼갠다.

### 3.2 기준 시점 — 전 시간 최대 + 피크 시각 병기

- 요소별로 **전 시간에 걸친 최대 von Mises** 를 구해 그 값으로 상위 X% 를 뽑는다.
- 각 덩어리에 그 덩어리의 최대값이 발생한 **시각**을 함께 기록한다.
- 시각별 군집 추적(핫스팟 이동)은 **이번 범위에서 제외.** 출력이 커지고
  현재 요구에 없다.

### 3.3 구현 위치 — KooD3plotReader

- 상위 백분위 추출은 `ValueFilter::inTopPercentile()` 로 **이미 존재**한다.
- d3plot 요소 응력·절점 좌표에 직접 접근할 수 있는 곳이 여기다.
- pyKooCAE 후처리 스크립트로 만들면 요소 전체 응력장을 다시 읽어야 해 비효율.

## 4. 기본값

| 파라미터 | 기본값 | 근거 |
|---|---|---|
| 상위 백분위 | 5 % | 요구사항 초기값 |
| 거리 임계 배수 | 1.5 × 요소 대표 크기 | 인접 요소는 묶고 한 칸 건너뛴 것은 분리 |
| 최소 덩어리 크기 | 5 요소 | 노이즈 제거. 미만은 버림 |
| 기준량 | von Mises | 상위 X% 선별 기준 |
| 보고량 | 응력 + 변형률 | 덩어리 안에서 둘 다 집계 |

변형률 기준으로 덩어리를 뽑는 것은 옵션으로 열되 기본은 응력 기준이다.

## 5. 산출물 형식

`analysis_result.json` 에 파트별 배열로 추가한다.

```json
"hotspot_clusters": [
  {
    "part_id": 23,
    "part_name": "INTERPOSER_PCB",
    "criterion": "von_mises",
    "top_percent": 5.0,
    "threshold_value": 312.4,
    "distance_threshold": 0.42,
    "element_size_ref": 0.28,
    "clusters": [
      {
        "rank": 1,
        "element_count": 47,
        "center": [12.34, -5.67, 1.02],
        "radius_enclosing": 1.21,
        "radius_rms": 0.63,
        "stress_mean": 381.2, "stress_max": 452.7,
        "strain_mean": 0.0121, "strain_max": 0.0198,
        "peak_element_id": 100234,
        "peak_time": 0.00135
      }
    ]
  }
]
```

`clusters` 는 최대 응력 내림차순 정렬.

## 6. 범위 밖 (이번에 하지 않는 것)

- 시각별 군집 추적 / 핫스팟 이동 경로
- "좌하단 / 우상단" 같은 **자연어 구역 라벨** — 상대 좌표까지만 제공하고
  라벨링은 소비 측(리포트 생성기)에서 판단
- 셸 요소 — 1차는 솔리드 대상. 셸은 후속
- 군집 결과의 시각화 렌더링

## 7. 검증 기준

1. **합성 덱** — 알려진 위치에 2개 덩어리를 인위로 만든 케이스에서
   중심 좌표와 개수가 기대와 일치
2. **경계 조건** — 상위 X% 가 0개, 전부 한 덩어리, 최소 크기 미달만 존재
3. **회귀** — 기존 `analysis_result.json` 의 다른 필드가 바뀌지 않음 (필드 추가만)
4. **실덱** — 실제 낙하 결과에서 덩어리 수와 위치가 단면 뷰 컨투어와 육안 일치
5. **성능** — 요소 수십만 규모에서 기존 분석 시간 대비 유의미한 증가 없음

## 8. 미해결 · 확인 필요

- **요소 대표 크기**를 무엇으로 정의할지 — 외접구 지름 / 부피의 세제곱근 /
  절점 간 평균 거리. 구현 시 실측으로 결정하고 노트에 기록
- 상위 X% 를 **파트별로** 계산할지 **전체 모델 기준**으로 계산할지 —
  파트별이 요구에 맞으나, 파트 간 비교가 필요하면 전체 기준도 옵션으로
